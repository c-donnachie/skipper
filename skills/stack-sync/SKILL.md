# Skipper :: stack-sync

Detectar el desfase entre lo que el proyecto **tiene instalado** (`package.json`) y lo que el bloque `skipper:stack` de `CLAUDE.md` **declara**.

## Reporte automático
!`bash "${CLAUDE_PLUGIN_ROOT}/lib/stack-sync.sh" "$(pwd)"`

## Tu tarea

Acabas de recibir el JSON del sincronizador. Interpreta y reporta.

### 1. Validaciones previas

- Si `package_json: false` → "No hay package.json en la raíz. stack-sync sólo aplica a proyectos Node." y termina.
- Si `has_block: false` → "No hay sección `<!-- skipper:stack -->` en CLAUDE.md. Corre `/skipper:stack-apply <id>` primero." y termina.

### 2. Reporta el desfase

Sólo importan las filas con `status` distinto de `ok`. Agrupa en dos tablas:

**📦 Instaladas pero NO documentadas** (`status: undocumented`) — librerías que el código usa pero el bloque no menciona:

| Librería | Categoría |
|---|---|
| react-native-reanimated | animation |
| ... | ... |

**👻 Declaradas pero NO instaladas** (`status: phantom`) — el bloque las menciona pero `package.json` no las tiene (removidas, reemplazadas o nunca instaladas):

| Librería | Categoría | Probable causa |
|---|---|---|
| zod | validation | nunca se instaló o se quitó |
| nativewind | styling | reemplazada por otra de la misma categoría (revisa `undocumented`) |

> Pista de juicio: si una `phantom` y una `undocumented` comparten `category`, casi seguro hubo un **reemplazo** (ej. `nativewind` → `uniwind`). Dilo explícitamente.

### 3. Ofrece arreglar (NO automático)

Después de las tablas, pregunta al usuario en **una sola pregunta**:

> ¿Actualizo el bloque `skipper:stack` para reflejar la realidad? (agrego las undocumented, quito/reemplazo las phantom)

Si dice que sí:
- Edita **sólo** el contenido entre `<!-- skipper:stack -->` y `<!-- /skipper:stack -->`.
- Agrega las `undocumented` a la categoría correcta de la prosa del bloque.
- Para `phantom`: si hay reemplazo claro, cámbiala por la nueva; si no, quítala.
- **NUNCA** toques nada fuera de los marcadores.
- No cambies el comentario `generated by skipper ...` salvo la fecha si la editas a mano.

Si dice que no, termina sin escribir.

## Output final

```
🐧 stack-sync:
  ✅ ok: N          (instaladas y documentadas)
  📦 undocumented: N (instaladas, faltan en el bloque)
  👻 phantom: N      (declaradas, no instaladas)

Siguiente paso:
  Confirmar para actualizar el bloque skipper:stack, o
  /skipper:stack-add <layer>   → si falta una capa opinada completa
```

## Reglas duras

- Read-only por defecto. Sólo escribes si el usuario confirma, y sólo dentro de los marcadores.
- No inventes causas: si no hay match de categoría para una phantom, di "causa desconocida".
- No reportes las filas `ok` en tablas — sólo cuéntalas en el resumen.
- El diccionario de librerías es acotado (las que skipper opina). Si el usuario usa algo exótico no listado, acláralo: "stack-sync cubre las librerías opinables comunes; no es un inventario completo".
